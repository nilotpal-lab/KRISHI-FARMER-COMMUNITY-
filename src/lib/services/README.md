# Core-only demo fixtures · P1

No real people, addresses, photos, keys or passwords. All member activity is fictitious and identified as such in-app. These fixtures **replace** the P1 fixture data from v1.0; do not import old photos, likes, replies, accounts, Learn content or AI preferences in P1.

- [fixtures.json](fixtures.json): **two members** (`gowri_demo`, `ravi_demo`) and **one admin** (`admin_demo`), six starter groups, 18 short text posts (six per language), six flat comments, and one harmless report seeded to test Dismiss. Core walkthrough uses a newly reported post for Hide, not the anchor post. `p01` is a soil-test discussion under Karnataka Farmers, used in the visual reference. Default groups in order: Karnataka Farmers, Maharashtra Farmers, Tamil Nadu Farmers, Tomato Growers, Onion Growers, Chilli Growers. Seeded group names/descriptions have authored labels in all three locales; posts are not translation pairs.
- [places.json](places.json): `states[]` with `key`, `kind=state|ut`, `labels:{en,kn,hi}`. Covers 28 states + 8 UTs with app-local slugs. No location data about the person, no district choices or GPS. Editorial state spellings to verify before field use.
- [ui-starter.json](ui-starter.json): core dictionary keys (`en/kn/hi`) for P1 affordances. Expand to cover every rule, validation and Later body using [02](../02-pages-and-controls.md) and test equal keys and copy; this is not a functional localization framework.

## Import contract

1. Apply [P1 schema and grants](../04-stack-data-and-security.md) to a verified dedicated target only. Verify JSON keys, relationships, locale and field bounds before any writes. Create each Auth account out of band with a unique private password and confirmed internal alias from username. Map returned UID to `profiles`/`private.demo_accounts`; seed active roles in a single DB transaction and note credentials in owner's password manager, never in app JSON. No script needs a hosted runtime admin key. Existing UID is reused on rerun; never reset passwords on seed rerun.
2. `communities[]` records `slug,kind,stateKey,seedOrder,labels` with each `labels[locale]={name,description}`. Store English primary DB name/description (`lang=en`), `created_by=NULL`, server uses static translation at display time for exactly the listed seed slugs. Import geography records first. Stable UUIDs with e.g. UUIDv5 namespace `a879c9d0-54aa-49dd-9521-e63af72756ba` + `community:<slug>`, `post:<key>`, `comment:<key>`, `report:<key>`; not Auth UID and not a secret. Derive dates from `SEED_BASE_UTC` (≤ now; set once) + relative offsets.
3. `posts[]` maps `{key,community,author,lang,title,body,offsetMinutes}` to `published`; `comments[]` maps `{key,post,author,lang,body,offsetMinutes}` with same post scope. No parent comments; no media fields. Initialize member/group relationships as the unique union of declared writers of posts/comments to their groups. Do not grant admin member permissions. `reports[]`: `{key,post,reporter,reason,status,offsetMinutes}`; one non-author Other report, no text/sensitive payload.
4. Dry-run before applying; seed explicitly, not on deploy or startup. Insert missing initial records once, never overwrite a hidden post, resolved report or membership removed by a demo user on normal reruns. Use a completion note/manifest and verify, not uncontrolled upserts. Repair a partial first run explicitly in isolation. Keep `.env.seed*` and exports out of Git. Distinguish approved reset on a disposable clone from the demo environment.
